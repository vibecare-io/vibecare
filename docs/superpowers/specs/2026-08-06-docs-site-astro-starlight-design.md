# Docs Site: Astro + Starlight — Design

**Date:** 2026-08-06
**Status:** Approved (design)
**Goal:** Render everything under `docs/` as a browsable documentation website using
Astro + the Starlight theme, launched with a single `just` command. Package manager: **bun**.

## Problem

`docs/` holds ~20 Markdown files (including nested `superpowers/` and `macos/` subdirs),
5 Org-mode files (`arch.org`, `backlog.org`, `braindump.org`, `ideas.org`, `init.org`), and a
binary `org-roam.db`. Reading these as raw files is painful. We want a single command that
serves them as a searchable, navigable site.

Constraints discovered:
- **bun 1.3.9** is available; **pandoc is NOT installed** (needed for `.org` conversion).
- Existing `.md` files are plain — first line is `# Heading`, **no frontmatter**. Starlight
  *requires* a `title` in each doc's frontmatter or the build errors.
- `.gitignore` already ignores `node_modules/`, `dist/`, `build/`, `*.db`.
- Justfile uses emoji-grouped recipes.

## Approach (chosen: A — sync script → generated content dir)

A single sync script populates `docs-site/src/content/docs/` from `docs/`. The repo `docs/`
directory stays the source of truth and is unchanged. The generated content dir is gitignored.
Dev/build recipes run the sync first.

Rejected: (B) Astro glob loader reading `docs/` in place — can't cleanly inject required
titles, and `.org` still needs a temp conversion dir; two source roots, more moving parts.
(C) Moving docs permanently into the Astro content dir — abandons `docs/` as canonical
location and breaks existing links + CLAUDE.md references.

## Layout

```
docs-site/                      # committed: astro + starlight scaffold
  package.json                  # bun; astro + @astrojs/starlight
  astro.config.mjs              # Starlight config, autogenerated sidebar
  scripts/sync-docs.mjs         # docs/ -> src/content/docs/ (copy md, pandoc org, inject titles)
  src/content.config.ts         # Starlight docs collection (docsLoader/docsSchema)
  src/content/docs/             # GENERATED, gitignored
  .gitignore                    # local ignores (content/docs, .astro, dist)
docs/                           # unchanged, source of truth
```

## Component: `scripts/sync-docs.mjs`

A Node/bun ESM script (run via `bun run`). Responsibilities:

1. **Clean** `src/content/docs/` to avoid stale/renamed files.
2. **Markdown** — for each `docs/**/*.md`, copy into the content dir preserving the relative
   subdirectory path.
3. **Org** — for each `docs/**/*.org`, convert to GitHub-flavored Markdown via
   `pandoc -f org -t gfm`, writing `<name>.md` into the content dir.
4. **Title injection** — for every output file, if it lacks YAML frontmatter with a `title`,
   derive a title from the first `# H1` heading; fall back to a humanized filename. Prepend a
   minimal `---\ntitle: "…"\n---` block. Existing frontmatter is preserved as-is.
5. **Homepage** — map `docs/README.md` → `src/content/docs/index.md` so the site root shows the
   documentation index.
6. **Skip** binary/non-doc files: `org-roam.db`, and anything that isn't `.md`/`.org`.
7. **pandoc guard** — if any `.org` files exist and `pandoc` is not on `PATH`, print a clear
   error (`brew install pandoc`) and exit non-zero.

Determinism: re-running the script fully regenerates the content dir from `docs/`.

## Component: `astro.config.mjs`

- Integrate Starlight with a site `title` ("VibeCare Docs") and description.
- **Sidebar:** `autogenerate` from the content directory so structure mirrors `docs/`
  (top-level pages + `superpowers/`, `macos/` groups). No manual sidebar maintenance.
- Built-in Starlight site search (Pagefind) enabled by default — satisfies "read all things
  inside docs easily".

## Just recipes (new group `📚 Documentation`)

- `docs-setup` — `cd docs-site && bun install`; check for pandoc and, if missing, attempt
  `brew install pandoc` (or instruct the user).
- `docs` — run sync, then `bun run dev` (Astro dev server with live reload; opens browser).
- `docs-build` — run sync, then `bun run build` (static site to `docs-site/dist/`).
- `docs-sync` — run the sync script only (internal helper the above depend on).

`package.json` scripts wrap the Astro CLI (`dev`, `build`, `preview`, and `sync` → the mjs).

## Error handling

- **Missing pandoc + org files present** → sync exits non-zero with `brew install pandoc` hint.
  If no `.org` files exist, pandoc is not required.
- **Missing title** → never fatal; handled by title injection.
- **Stale files** → cleaned each sync run.

## .gitignore additions

Global `node_modules/`, `dist/`, `build/`, `*.db` already cover most. Add a local
`docs-site/.gitignore` (or repo entries) for:
- `src/content/docs/`  (generated)
- `.astro/`

## Testing / verification

- `just docs-setup` installs deps cleanly.
- `just docs-sync` produces `src/content/docs/` with every `.md` and each `.org` converted,
  each having a `title`; `org-roam.db` absent.
- `just docs` serves the site; nested docs render, sidebar reflects the tree, search works.
- `just docs-build` produces a static build with no Starlight title/frontmatter errors.

## Out of scope (YAGNI)

- Custom theming/branding beyond Starlight defaults.
- Deploying/hosting the site.
- Org-roam graph or `.db` visualization.
- Converting `.org` files permanently (kept as-is; converted on the fly).
